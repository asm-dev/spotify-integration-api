# Spotify Integration API

RESTful API to query songs/artists and perform CRUD operations on the user's favorite songs through the Spotify integration. Built with FastAPI.

![Screenshot 2024-12-06 192528](https://github.com/user-attachments/assets/5ef2576b-5d35-48f1-b6d0-aefbe5f13339)

## Installation

### Requirements
- Python 3.8 or higher.
- Spotify developer account to obtain the API client ID and client secret.

### Configuration
1. Clone the repository.
2. Create a .env file and add your Spotify API access credentials.
   
   ```
   SPOTIFY_CLIENT_ID="tu_client_ID"
   SPOTIFY_CLIENT_SECRET="tu_client_secret"
   ```
3. Install the dependencies. Installing some of them may also install associated libraries.

   ```bash
   pip install -r requirements.txt
   
## Usage

1. Launch the server at `http://127.0.0.1:8000` with the following command:
   ```
   python launch.py
   ```
2. Once the login is resolved you should be redirected automatically to `/login`, but if that doesn't happen due to your IDE or machine configuration, please navigate there manually. This step is very important, since without the token you won't be able to access the endpoints.

3. Explore the application.

   - You can access the interactive documentation auto-generated by FastAPI in Swagger UI at `http://127.0.0.1:8000/docs`. Alternatively, you can use extensions such as RapidAPI.
   
   - If you want to do a quick behavior test you can try going to `http://127.0.0.1:8000/search?q=Coldplay&type=artist&limit=5` or `http://localhost:8000/top-tracks?time_range=short_term&limit=3`
   
   - `/save-top-tracks` lets you store your favorite songs in a JSON file. Once stored, you can create, read, delete or update these songs using several endpoints available in the application.

## Main Endpoints

**Login and callback**, GET:
    
*   They handle user authentication, relying on functionality found in `spotify_service.py` (SSP)
    
    *   `/login`: Redirects the user to Spotify to authenticate.
        
    *   `/callback`: Processes the authorization code and stores the API access tokens.

**Search songs or artists on Spotify**, GET:

*   `/search`: based on a search term `q`, searches for songs or artists. The `type` search parameter allows searching by "track", "artist", etc.; by default it searches for songs. `limit` refers to the maximum number of results (5 by default)
    

**Get the user's most played songs**, GET:
    
*   `/top-tracks`: retrieves the user's most listened-to songs. By default this endpoint returns the top 10 songs listened to in the last 6 months, but this can be changed by setting `time_range` to short\_term or long\_term, and the number of results by setting `limit`.


**Save the user's most played songs**, GET:

*   `/save-top-tracks`: gets the user's most listened-to songs from the Spotify service using the `/top-tracks` endpoint. The received songs are saved in a `user_songs.json` file. Each song is added to the file using the `POST /songs` endpoint, which keeps an up-to-date list of the user's favorite songs.


**CRUD operations on a list of songs**:

*   **Create**, POST: `/songs`

*   **Read**, GET:  `/songs` and `/songs/{song_id}`

*   **Update**, PUT: `/songs/{song_id}`

*   **Delete**, DELETE: `/songs` and `/songs/{song_id}`

## Application of SOLID principles 

- **Single Responsibility**, SRP:  
   - `main.py` focuses on handling the REST API and user interactions.
   - `spotify_service.py` manages communication with the Spotify API, for example, handling the access token.

- **Open/Closed**, Open/Closed: it is easy to add new endpoints or services without having to change existing functionality, which makes expansion easier.

- **Liskov Substitution**, Liskov Substitution: although classes are not used, modular design principles are followed since modules or components could be replaced by others without affecting the functionality of the rest.

- **Interface Segregation**, Interface Segregation: each function has a clear and specialized responsibility, for example `generate_auth_url`.

- **Dependency Inversion**, Dependency Inversion: the logic in `main.py`is decoupled from the implementation details of the Spotify API logic in the `spotify_service.py` service.
